# CHG-3412 — Legacy-RDV sur Kubernetes (recette, production prête)

| Champ | Valeur |
|---|---|
| Catégorie | normal |
| Risque | moyen (nouvel opérateur de base, application monolithique) ; aucun impact cabinets (recette et production sans trafic) |
| Fenêtres | aucune coupure : déploiements hors production, puis production à zéro trafic |
| Retour arrière | Applications Argo CD supprimées sans élagage des PVC (Prune=false) ; opérateur retiré (CRD gardées tant qu'un objet existe) |

## Décisions (ADR courte, reprise dans ADR-0340)
- **Base** : mariadb-operator 26.6 (MIT, CRD déclaratives `Database`/`User`/`Grant`/`Backup`, sauvegardes S3 intégrées) plutôt qu'un StatefulSet fait main (sauvegarde, comptes et droits à écrire soi-même) ou que la base de la VM (Debian 12). **Une** instance : pas de Galera pour 40 cabinets ; disponibilité = sauvegarde quotidienne + restauration éprouvée (RTO mesuré : <N> min). Pas de PDB sur la base (il bloquerait les drains).
- **Sessions** : dans MariaDB (`inc/sessions.php`, `SessionHandlerInterface`, table `sessions`), sans extension PHP ni nouveau composant. Valkey écarté : extension `redis` à compiler dans l'image, un service de plus pour 40 cabinets. Perte du verrou de session de PHP « files » : sans effet ici (jeton CSRF, message).
- **Pièces jointes** : PVC `cephfs` RWX (M16) ; stockage objet (RGW) noté pour la réécriture (ADR-0340).
- **« Maintenant »** : calculé par PHP dans le fuseau des cabinets, passé à la requête : la comparaison avec les `DATETIME` sans fuseau ne dépend plus du fuseau du serveur (MariaDB en conteneur = UTC par défaut). La base a en plus `timeZone: Europe/Paris`.
- **Mots de passe** : générés par OpenBao, source de vérité `kv/legacy/<env>/mariadb` (root, application, migrateur), livrés par ESO ; l'opérateur ne génère rien (`generate: false`). Le mot de passe de 2014 n'existe plus nulle part sur Kubernetes ; il disparaîtra avec la VM (F4-S14).
- **Purge** : CronJob qui met la base à jour en même temps que le disque, nettoie les références orphelines d'InfoGér de plus d'un an, signale les références récentes sans fichier, purge les sessions expirées.

## Mesures
Recette : 2 pods sur 2 nœuds, `/sante.php` 200, `/pret.php` 200 ; test « deux réplicas » (10 formulaires consécutifs, jamais « session expirée ») ; restauration de la sauvegarde dans `wb-essais` : <N> rendez-vous, identique.
