# ECA-3603 — Sauvegardes Velero et exports non chiffrés côté serveur

## Constat (auditeur)

Les sauvegardes Velero (`velero-k8s-par1`, Kopia) et les exports (dumps, archives) sont déposés sur le
stockage objet **sans chiffrement côté serveur** : un administrateur du stockage objet lit des données
de santé en clair.

## Risque

Fuite de données de santé par un accès (légitime ou non) au stockage objet, sans compromettre le
cluster ; une sauvegarde dérobée est exploitable telle quelle.

## Remédiation (SEC-3609, F6-S09)

1. Dépôt Kopia de Velero chiffré par une phrase de passe tirée d'OpenBao (`kv/velero/depot/phrase`,
   injectée par ESO) : `s3-01` / le RGW ne voient que du chiffré.
2. Exports bruts chiffrés par `age` dans le pipeline (clé privée dans `kv/exports/age`).
3. Restauration éprouvée (Velero : `medidoc-dev` ; export `age` : essai déchiffré).

## Preuve de clôture

Collectée par `ms-preuves` dans `preuves-conformite/ECA-3603/` :
- configuration du dépôt chiffré de Velero (sur `main`) ;
- journal de la restauration d'essai réussie ;
- vérification qu'un objet du dépôt lu depuis `s3-01` est bien chiffré (pas de donnée en clair).
